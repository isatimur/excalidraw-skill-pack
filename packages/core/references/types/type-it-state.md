# IT State / Operating Model

Use IT state to contrast current and target operating conditions across capabilities, not to catalogue tooling. Use active-theme `palette.md` warning, inactive, AI, neutral, and success colors by meaning.

## Layout
- Use two frames: current state and target state. Align the same 4–7 capabilities vertically.
- Put the transition thesis in the center: what changes in ownership, automation, reliability, or cost.
- Keep capability labels free-floating; reserve containers for pivotal platforms or controls.

## Excalidraw pattern
- Skeleton shapes with bound labels represent systems only where they carry the argument.
- Orthogonal arrows show migration or control relationships; dashed governance (theme connector stroke) shows governance.
- Include one current/target evidence pair: config, SLA, incident metric, or payload.

## Avoid
- Vendor-logo walls, unmeasurable future claims, and mixing migration sequence into the state comparison.

## Budget
4–7 capabilities, 1–2 evidence pairs, one target operating thesis.
