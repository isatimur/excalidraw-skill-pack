# Process

Use a process to argue a transformation with a beginning and end, without decision-heavy branching. Pull input, action, success, and warning colors from the active theme's `palette.md`.

## Layout
- Compose a left-to-right assembly line: input, 3–6 transformations, outcome.
- Keep step explanation and metrics as free-floating text beneath the spine.
- Frame phases where a handoff or change in method matters.

## Excalidraw pattern
- Skeleton shapes use bound labels for material steps; arrows route orthogonally between them.
- Use a dark evidence card for a concrete input/output, command, or payload.

## Avoid
- A chain of generic boxes, unproven transformations, and decision branches that belong in a flowchart.

## Budget
4–8 primary steps. Split optional paths into another diagram.
